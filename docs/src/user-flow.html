Screens

#ScreenPurpose and key elements
S1Onboarding & Sign in3 short intro slides (first launch only), then e-mail or Google sign-in / sign-up.
S2My Groups (home)List of groups with the user’s balance per group; empty state when there is none; bottom navigation.
S3Create groupGroup name, optional emoji/colour, invite members by link or QR code.
S4Join groupEnter invite code, scan QR or open an invite link; shows group preview before joining.
S5Group detailHeadline balance, expense list, members, extended FAB “Add expense”, link to Balances.
S6Add expenseAmount, title, paid by, split rule (equal / custom), optional receipt photo, date.
S7Balances & Settle upMinimal list of payments (who pays whom), “Settle” button with confirmation dialog.
S8ActivityChronological feed of expenses, edits and settlements across all groups.
S9Profile & SettingsName, currency, language (TR/EN), theme, notifications, sign out.

Decision points

#DecisionOutcomes
D1Signed in?No → S1 (onboarding, sign in). Yes → straight to S2.
D2Has a group?No → empty state offering Create (S3) or Join (S4). Yes → S5 group detail.
D3Split rule?Equal → save immediately. Custom → custom split sheet (amounts or %).
D4Total = amount?Yes → save. No → show the remaining difference inline and stay on the sheet.
D5Open debts?Yes → settle up (record payment, confirm). No → “All settled” state.

Edge cases handled in the design

OfflineAn expense added without network is stored locally and synced later (“Waiting to sync” chip).
Camera deniedIf receipt-photo permission is refused the user can still save the expense without it.
Invalid inviteExpired or wrong code shows an inline error and a “Try again” action.
CancelClosing the Add-expense sheet with unsaved input asks for confirmation (“Discard?”).
